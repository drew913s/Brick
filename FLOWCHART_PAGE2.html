1 New or Existing Code?
Decide which Queen mode to use
Check what exists:
ls -la find . -name "*.py" -type f | head -20 git log --oneline -5 2>/dev/null || echo "No git"
Existing code with no brick structure → Audit mode
2 Spawn Queen (New Project)
Architecture design, no code
Open new terminal in Brick repo:
cd ~/Brick && claude
Then type:
/user:queen
Then describe what you're building.
3 Spawn Queen (Audit Mode)
Map existing code first
Open new terminal in Brick repo:
cd ~/Brick && claude
Then type:
/user:queen-audit
Share the codebase path or file tree.
4 Review GitHub Issues
Pick next task from BACKLOG
List open issues:
gh issue list --state open gh issue list --label "worker"
View specific issue:
gh issue view [NUMBER]
Domain issue → spawn with /user:princess
Worker issue → spawn with /user:ant
5 Check Dependencies & Files
Safe to spawn?
Check if dependency issues are DONE:
gh issue view [DEP_NUMBER] --json state
Check file conflicts with running workers:
# Look at your tracker - do any running # workers own files this task needs?
File overlap? → WAIT or pick different task
6 Spawn Worker
New terminal + slash command + task
1. Open new terminal:
cd ~/Brick && claude
2. Load role:
/user:ant
3. Paste the issue content or say:
My task is issue #[NUMBER]
4. Update tracker + GitHub:
gh issue edit [NUM] --add-label "in_progress"
7 30-Min Check: Active?
Is worker still working?
Check terminal: Any recent output?
Check git (in worker's directory):
git log --oneline -3 --since="30 minutes ago" git status
Check GitHub issue for updates:
gh issue view [NUMBER] --comments
8 Abandon (Silent Worker)
Can't recover → close and respawn
1. Save any work first:
git add . git commit -m "WIP: Q-XX-N partial before abandon"
2. Close the terminal
3. Update issue:
gh issue comment [NUMBER] -b "Abandoned: [reason]. Respawning."
4. Go back to Step 6 (respawn)
9 Prompt Silent Worker
Nudge if recoverable
Type in the worker's terminal:
/user:status
Or just ask:
What's your progress? Any blockers?
10 Check Abandon Triggers
Bad signs → abandon
ABANDON if worker:
□ Argues about approach □ Philosophizes instead of coding □ Claims "done" but no working code □ Same error 3x in a row □ Touches files outside ownership □ 30+ min no commits or updates
Any checked? → Step 8 (Abandon)
11 Check: CODE_COMPLETE?
Worker says done - verify files exist
Check files were created:
ls -la bricks/[domain]/[expected_files] find . -name "*.py" -mmin -60
Check tests exist:
ls -la bricks/[domain]/test_*.py
Check committed:
git status git log --oneline -3
12 HUMAN Test
Run it. Click it. Break it.
Run tests:
python -m pytest bricks/[domain]/test_*.py -v
Run the actual code:
python -c "from bricks.[domain].[brick] import [func]; print([func](test_input))"
For UI components:
python app.py # or whatever starts it # Then actually click through it
13 Works?
Your judgment call
Ask yourself:
□ Tests pass? □ Code runs without errors? □ Does what the issue asked for? □ Doesn't break other stuff?
All yes → Step 15 | Any no → Step 14
14 Create Fix Issue
Document what's broken
Create new issue:
gh issue create --title "[FIX] Q-XX-N: [problem]" \ --label "worker" --label "fix" \ --body "Parent: #[ORIGINAL] ## Problem [what's broken] ## Expected [what should happen] ## Files [which files need fixing]"
Go back to Step 4
15 Mark DONE
Update GitHub, close terminal
Update labels:
gh issue edit [NUMBER] --remove-label "in_progress" gh issue edit [NUMBER] --add-label "done"
Close issue:
gh issue close [NUMBER] -c "Verified working by HUMAN"
Update your tracker: mark row DONE
Close worker terminal
Go back to Step 4 for next task
Emergency Commands
git tag chaos-$(date +%m%d%H%M) # snapshot before reset git stash # save uncommitted work git reset --hard HEAD~1 # undo last commit
